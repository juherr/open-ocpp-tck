# OCA-201-SLICE -- which OCPP 2.0.1 certification cases this suite may
# implement, and which scenario implements each.
#
# THIS FILE IS THE LIST. OCA-201-SELECTION.md states the RULE it is drawn from
# -- role CSMS, status M in Part 5 §4's `Conf. test for CSMS` column, on every
# certification profile -- and cites this file rather than restating it. The
# same arrangement OCA-COVERAGE.md has with OCA-OBLIGATIONS.txt, for the same
# reason: two copies of a list drift, and the prose copy is the one nobody
# diffs.
#
# THE RULE SELECTS 147 CASES AND THIS FILE HOLDS 147. It stopped being a
# bounding list and became the pool when the matrix was re-parsed to keep the
# case identifier per row rather than only the per-profile count -- Part 5
# Edition 4, 2025-12-03, by the method on that page. Note what the same run
# corrected: the totals it replaced summed to 205, because three of the four
# profiles had been counted on the charging station's column. Whether a list
# this long may be committed at all was the other half of the gap, and it is
# settled: it may. CC BY-ND limits modification, not extent, and a list of case
# identifiers modifies nothing -- the argument, and the one risk it accepts,
# are in that page's "What may be committed here, and what may not".
#
# 147 CASES, 165 ROWS OF THE MATRIX. Thirty-seven cases are listed under two
# profiles, all of them Smart Charging and ISO 15118 Support, and nineteen of
# those are mandatory for this role in at least one. A case is a case, so it
# gets one row -- which is also all this file can hold, since the guard refuses
# a second row for a case already listed.
#
# Hand-maintained, and guarded: tests/oca-201-slice.sh reads it against
# tck/specs/ASSERT-INVENTORY.txt in both directions, so a `cert201-` scenario
# for a case that is not listed here and a case here that is neither
# implemented nor declined are both build failures.
#
# WHAT NO GUARD CAN CHECK: that these rows ARE mandatory CSMS cases the rule
# selects, and that they are ALL of them. That is a reading of a PDF this
# repository does not contain -- a reference is cited by URL and not committed,
# and OCA-201-SELECTION.md's licensing section says why that is our rule rather
# than the licence's -- and the method for redoing the reading is written down
# on that same page, now with the edition it was last run against. Note the
# second half: the guard ranges over this file, so a file short of the pool is
# a file it finds complete, and that this file is no longer short is a claim
# only a re-run of the parse can check. What is checked is that the list and
# the scenarios stop drifting afterwards.
#
# NOTHING OF THE REFERENCE'S OWN WORDS IS HERE, which is what leaves a row on
# the identifiers-and-counts side of the line that page draws. A reason below
# says what THIS suite lacks; none of them says what a case asks for.
#
# A row is three fields, the third free text:
#
#   <OCA case>  <templateId | not-implemented>  <why not, on a not-implemented
#                                                row; omitted on an implemented
#                                                one, where the scenario says it>
#
# A REASON IS WRITTEN PER GROUP, NOT PER CASE, and the repetition below is that
# rather than a placeholder. Twenty-two reasons cover the 140 declined rows,
# because that is the granularity the decision was actually taken at: a block's
# cases are blocked by one missing thing -- an operation the three-member
# `CsmsOperation201` union does not have, a station-side event no simulator
# template can produce, a transport seam that does not exist. Splitting one
# reason into ten copies with the case id changed would read as ten decisions
# and be one. If a case is blocked by something its neighbours are not, it gets
# its own row text; TC_B_58, TC_F_27 and TC_G_20 already do.
#
# WHICH RESET OUTCOME IS WHICH CASE IS OUR READING, not something read off Part
# 6. `ResetStatusEnumType` has three values and the Reset block has three
# mandatory CSMS cases, so they are mapped Accepted / Scheduled / Rejected in
# case order. tck/specs/core-201.ts's header carries the argument. Correcting
# it moves three rows here and three templateIds there.
#
# case / scenario / why not
